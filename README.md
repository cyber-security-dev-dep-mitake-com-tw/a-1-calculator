# A-1 通路利潤試算機

硬體 + 訂閱的混合商業模式,在多階通路下算單位經濟。回答四個問題:

| 頁面 | 回答 |
|---|---|
| **定價決策**(首頁) | 目標毛利下 MSRP 該訂多少 |
| **通路折扣底線** | 最多能讓代理商幾 % |
| **市場進入比較** | 先進哪個國家 |
| **3 年財務預測** | 現金夠不夠 |

```bash
npm install
npm run dev      # http://localhost:5173
npm run test     # 模型單元測試
npm run build
```

## 為什麼計算與畫面要分開

財務數學全在 `src/model/` 的純函式,由 Vitest 測試;React 只負責輸入與呈現。
這種試算機最大的風險是**算錯而沒人發現** —— 畫面依然有數字,但稅含內外、折扣疊加順序、
幣別換算方向都可能寫反。測試釘住的正是這些:

- 稅**含內 vs 外加**:同一稅率兩種算法必須不同且各自正確(台灣內含 / 美國外加)
- 三階折扣**不可連乘**:原廠實收只看總代折扣,經銷折扣決定的是通路內部怎麼分
- 金流**固定費**:超商 / ATM / 電匯是固定費,低單價品項用百分比估會嚴重失真
- 反推 MSRP 與正算瀑布**互為逆運算**(round-trip)
- 帳期拉長只影響現金曲線,**不影響認列損益**

## 預設值來源

訂閱價格取自 A1 Portal **現行硬編碼**的方案(`Portal/server.mjs`),不是估計:

| | |
|---|---|
| `personal-30` / `90` / `365` | NT$299 / 799 / 2,499 |
| 企業版 | `seat_count × term_days × 100` = **NT$1/席/天(≈30/月)** |
| 金流商 | Stripe、LINE Pay(`PAYMENT_SANDBOX.md`) |

硬體成本、稅率、匯率、通路折扣為**可編輯的起始假設**,依一般公開資訊填寫,
非市場調查或稅務意見 —— 請以實際報價與會計師確認後覆寫。

## 開發過程中,模型被實際數字修正過兩次

兩處都是跑起來看到荒謬數字才發現的,已補上測試:

1. **B2B 固定費未攤提** — NT$300 電匯手續費原本按「每席每月」收,讓 NT$30 的企業席次
   出現 −1059% 毛利。實際上一張通路訂單涵蓋多個單位,固定費要攤提
   (`payment.b2bUnitsPerOrder`)。修正後是 −14.8%,那才是真正的定價問題。
2. **市場比較未等值定價** — 原本把 MSRP 的數字原封不動當成各地當地幣,等於在英國賣
   2,000 英鎊、越南賣 2,000 越南盾。改為以 TWD 等值換算後,毛利差異才真的來自
   稅制與金流,而非定價高低。

另外 `runForecast` 的帳期索引曾有 off-by-one(帳期 0 時硬體貨款永遠收不到),
由「帳期拉長應壓低現金最低點」這條測試抓到。
